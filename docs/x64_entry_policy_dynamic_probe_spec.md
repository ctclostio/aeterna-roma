# x64 guest32 entry-policy DLL-boundary probe

Status: frozen implementation contract for the milestone after the static
entry-policy selector. This is a test-only diagnostic boundary, not recovered
game startup.

## Objective

Execute the already-tested `0x100edd70` entry-policy decision across a real
Windows x64 DLL call boundary. Add two test-only PE32+ AMD64 artifacts:

- `rome2_guest32_probe64.dll`;
- `rome2_guest32_probe_host64.exe`.

The host loads the probe by absolute and working-directory-relative paths,
resolves its exact named exports, supplies caller-owned read-only bytes plus
explicit guest32 coordinates, checks results, and unloads it. The probe calls
`rome2_port_100edd70_select_invalid_parameter_policy`; it does not reproduce a
second selector.

Both artifacts are native x64. “guest32” describes the modeled addresses and
data cells, not the executable architecture. An x64 process cannot load a true
x86 DLL, and loading the original engine would run its CRT/DLL initialization
outside the accepted startup boundary.

## Frozen diagnostic ABI

The DLL exports exactly these two names. Export ordinals are implementation
local, are never used by the host, and make no claim on the original 1-522 ABI.

```c
uint64_t Rome2Guest32ProbeAbiVersion(void);

uint32_t Rome2Guest32ProbeSelectEntryPolicy(
    const uint8_t *host_base,
    uint32_t guest_base,
    uint64_t byte_count,
    uint32_t command_line,
    uint32_t *policy_out);
```

`Rome2Guest32ProbeAbiVersion` returns `0x00010000`. The selector adapter returns
the existing numeric `rome2_guest_status`: `OK=0`, `BAD_ARGUMENT=1`,
`NULL_ADDRESS=2`, `RANGE_OVERFLOW=3`, or `OUT_OF_RANGE=4`. Policy values remain
`INSTALL_HANDLER=0` and `SKIP_HANDLER=1`.

`host_base` is a borrowed native x64 pointer to `byte_count` genuinely readable
bytes in the calling process. The other address parameters model x86 values.
The adapter constructs a local `rome2_guest_read_view`; it never derives a host
pointer from a guest value. `policy_out` is assigned only on `OK` and is
unchanged on every failure. No exported struct, Windows `wchar_t`, allocator,
CRT object, persistent state, callback, or ownership transfer is permitted.

## Canonical requirement IDs

All oracle, submission, review, and integration artifacts use these IDs:

- `DP-PROV-001`: pinned original/canonical/selector provenance runs first;
- `DP-ARCH-001`: probe host and DLL are PE32+ AMD64 while guest addresses and
  policy/status cells retain their frozen fixed widths;
- `DP-ABI-001`: exact two-name diagnostic ABI, version, status, and policy
  values;
- `DP-SEM-001`: the adapter delegates to the one bounded recovered selector
  and preserves its exact early-stop behavior;
- `DP-MEM-001`: borrowed native input, checked guest arithmetic, no
  guest-to-host conversion, and input/output preservation;
- `DP-LOAD-001`: absolute and relative name-based load/resolve/call/unload;
- `DP-TEST-001`: frozen behavior, high-address, repetition, and concurrency
  matrix with independent expected data;
- `DP-PE-001`: independent architecture/export/import/object-membership gate;
- `DP-CONT-001`: `BUILD_TESTING`-only containment and byte-identical inert
  bootstrap before and after;
- `DP-NOGO-001`: no original DLL load, initializer, handler, legacy entry,
  unrelated slice, middleware, or gameplay execution.

## Required dynamic tests

Expected case data is frozen in the host test and must not be generated by a
second selector implementation. Exercise through `LoadLibraryEx` and
`GetProcAddress`:

- exact literal including the terminator selects skip;
- empty, proper-prefix, appended-suffix, ASCII-case, leading/trailing-space,
  and quoted inputs select install;
- a first mismatch succeeds with exactly two readable bytes;
- a later mismatch succeeds without touching an unavailable suffix;
- missing terminator, one-byte final unit, and truncated interior unit fail;
- an unaligned address and a view ending exactly at `2^32` succeed;
- null arguments/address, malformed guest extent, numeric host-range overflow,
  and required checked-address overflow fail;
- every failure preserves the output canary and every call preserves input
  bytes;
- a genuine native allocation above 4 GiB succeeds without truncation;
- repeated and concurrent calls are deterministic and stateless;
- absolute and relative load/resolve/call/unload cycles both pass;
- the ordinary `empire.retail64.dll` smoke tests pass before and after the
  probe.

The DLL is silent. The host may emit deterministic per-case diagnostics, but
assertions and its exit code are authoritative.

## Build and containment

- Compile the probe and host as x64 C17 with `/W4 /WX /sdl /GS /guard:cf` and
  the repository's hardened link options.
- Create the targets only under `BUILD_TESTING`; do not install or package them.
- Link the static archive normally, never with `/WHOLEARCHIVE`, and prove the
  unrelated `ported_1093c450` object is not admitted to the probe DLL.
- Keep normal CRT startup. A trivial user `DllMain` returning `TRUE` is allowed,
  but it may perform no recovered work under loader lock.
- The original PE files, canonical stage, export contract, and startup audit
  are immutable.
- `empire.retail64.dll`, `rome2_host64.exe`, their source/definition files,
  sparse exports, imports, `DllMain`, inert `entry_point`, fingerprint, and
  status string remain byte-for-byte and behaviorally unchanged.

This contract supersedes only the static selector contract's statement that
the selector may be linked solely by a CTest executable: the new diagnostic DLL
is also allowed. It does not authorize linkage into `empire.retail64.dll`.

## Non-goals and hard rejection conditions

The probe must not call the inert legacy entry point, `0x100ed3c0`, handler
installation, recovered initializers, or the `0x1093c450`/`0x100e81a0` slice.
It must not load the original x86 engine/launcher, expose legacy aliases, infer
a legacy prototype, or add filesystem, registry, COM, process, network,
middleware, or gameplay behavior.

Reject guest-to-host casts, widened guest cells, unchecked guest arithmetic,
unbounded scans, writable/global arenas, input mutation, output mutation on
error, warning suppression, canonical edits, bootstrap linkage, or tests that
are their own only oracle.

The dynamic probe must pass before any real x64 startup linkage. The audited
initializer closure and `0x100ed3c0` path are not yet safe to execute.
