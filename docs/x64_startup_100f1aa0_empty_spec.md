# Empty-source sequence copy (`0x100f1aa0 -> 0x100ef330`)

Status: bounded test-only implementation contract. This is the next leaf-first
milestone after the accepted `0x100f1c10` triplet writer. It does not make
either recovered function generally callable and does not authorize startup or
gameplay execution.

## Objective and stop line

Port only the behavior reached when the first little-endian guest32 cell of the
source sequence is zero. Original `0x100f1aa0` copies that count to the
destination and calls `0x100ef330`. The helper copies the zero count to the
second destination cell and stores guest identity `0x11af4090` in the third.
The observable result is exactly `{0, 0, 0x11af4090}`.

The native wrapper must not reproduce those writes. After all wrapper-specific
validation, it delegates the final mutation to the accepted
`rome2_port_100f1c10_initialize_triplet` implementation. The test oracle is an
independent literal byte array
`00000000000000009040af11`; it is never generated by calling either port.

Any nonzero source count is `BAD_ARGUMENT`. In particular, the wrapper never
reaches, models, or substitutes for the nonempty branch beginning at
`0x100ef347`, which allocates through `0x100fcc80`. It does not inspect,
dereference, or cast the guest identity in source cell three.

## Native API and memory contract

The wrapper reuses `rome2_guest_addr32`, `rome2_guest_status`, and the accepted
`rome2_guest_write_view`:

```c
rome2_guest_status rome2_port_100f1aa0_copy_empty_source(
    const rome2_guest_write_view *view,
    rome2_guest_addr32 guest_destination,
    rome2_guest_addr32 guest_source,
    rome2_guest_addr32 *guest_return_out);
```

One borrowed writable view contains both complete 12-byte guest spans. The
source and destination must be disjoint; exact adjacency in either order is
valid. The wrapper byte-assembles only source bytes zero through three as a
little-endian count. Source bytes four through eleven are ignored and remain
unchanged. No guest coordinate is converted to a host pointer.

The view descriptor, its native interval, and the output cell must be pairwise
non-overlapping. This stricter wrapper boundary prevents self-referential
descriptor mutation before delegation. All guest, native-host, output-cell,
and descriptor interval arithmetic is checked before the source count is read.

Status precedence is frozen:

1. null view, output, or host base: `BAD_ARGUMENT`;
2. guest view wider than 2^32, guest end above 2^32, or numeric native host,
   output, or descriptor end overflow: `RANGE_OVERFLOW`;
3. output/view, output/descriptor, or descriptor/view native alias:
   `BAD_ARGUMENT`;
4. zero source or destination guest address: `NULL_ADDRESS`;
5. either guest address below the view or either 12-byte span outside it:
   `OUT_OF_RANGE`;
6. source/destination guest-span overlap: `BAD_ARGUMENT`;
7. nonzero source count: `BAD_ARGUMENT`;
8. otherwise delegate once to the accepted triplet writer and return its
   status.

For all valid, nonconcurrently mutated inputs, every failure preserves the
entire native view, its descriptor, and `guest_return_out` byte-for-byte. On
success, only the 12 destination bytes and the separate output cell change;
the complete source span and every other view byte remain unchanged.

## Canonical requirement IDs

- `ST2-PROV-001`: exact PE, canonical rows/sources, bodies, zero branch,
  rel32 targets, allocator boundary, and parent sites are authenticated first;
- `ST2-ARCH-001`: the host is x64 while all guest coordinates, cells, and
  identity values remain exactly 32 bits;
- `ST2-SEM-001`: count zero produces exactly the literal triplet and unchanged
  guest destination return through the accepted delegate;
- `ST2-EMPTY-001`: every nonzero count is rejected before any mutation and no
  source payload or guest pointer is followed;
- `ST2-MEM-001`: both complete spans share one checked view, remain disjoint,
  and all failure paths preserve view and output;
- `ST2-DELEGATE-001`: the accepted `0x100f1c10` port is the only allowed call
  and the only writer;
- `ST2-CONT-001`: all new sources and links remain `BUILD_TESTING`-only, with
  no legacy/probe export or bootstrap dependency;
- `ST2-NOGO-001`: no nonempty allocation, original-function execution, parent
  startup, platform, middleware, initializer, launcher-entry, or gameplay path.

## Required tests and reciprocal mutants

Runtime coverage includes source/destination adjacency in both orders,
genuinely unaligned host and guest coordinates, an end exactly at 2^32, all
0-through-11-byte short spans, below-base/null/range-overflow cases, exact and
partial overlap, multiple nonzero counts with each byte position exercised,
native output/descriptor/view alias cases, guard-page placement, a real native
allocation above 4 GiB, repetition, and concurrent independent calls. Every
failure snapshots the entire view and output.

The reciprocal static suite rejects at least: accepting a nonzero count,
partial or widened count decode, reading source payload, direct/partial/early
writes, a wrong or missing delegate, 8- or 16-byte spans, absent or off-by-one
overlap checks, unchecked native overflow, guest-to-host casts, allocation,
global state, platform calls, native-width API fields, DLL annotations, shared
or production linkage, `BUILD_TESTING` escape, and any new legacy or probe
export.

## Build containment

`rome2_startup_100f1aa0_empty_runtime` is a separate static library created
only inside `if(BUILD_TESTING)`. It links privately to
`rome2_startup_100f1c10_runtime`; its only consumer is the dedicated runtime
test executable. It is absent from the bootstrap DLL, host, guest32 probe,
production export contract, and legacy export definition. A post-runtime PE
gate and bootstrap-load smoke re-authenticate the unchanged production
artifacts.

## Acceptance result

The hardened Release build passes 29/29 CTest cases. The new six-test fixture
chain runs raw provenance, the eleven-test reciprocal static-gate suite, the
static gate itself, the native runtime matrix, a post-runtime PE/hash check,
and a final bootstrap load smoke.

A fresh `BUILD_TESTING=OFF` configure and build contains no `100f1aa0`,
`ported_100f1aa0_empty`, or `startup_100f1aa0` build edge, artifact name, or
generated test entry. The authenticated production artifacts remain unchanged
in the primary build:

- `empire.retail64.dll` SHA-256
  `fa4c0584790894e85a60427e0cb6adbf1266d14ddc321c122206365bdca8e3a0`;
- `rome2_host64.exe` SHA-256
  `007b75d58e6cb6890d98b102f07fd2be353423c4f31af41f11c366679a567708`.

This closes only the empty-copy seam. The parent remains inert, and the next
milestone must select another independently bounded dependency or add an
explicit platform/data seam before any startup-loop integration.
